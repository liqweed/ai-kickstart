Design rationale

Short arguments for §3.1–§3.9 of the brief, each tied to the success criteria in 05.

3.1 · Information architecture: one front door, one companion, one reference

Eight sibling pages put “Why”, “The system” and “Harness plan” at the same level as “Setup”, so a beginner has to guess. I collapse them into five places with distinct jobs: Start (understand + choose), Your setup (a personalised companion), Ideas menu, Prompts, and How it works (all depth: interview, harness, system, principles). Friend-with-the-link: Start answers everything and ends in a choice. One setting up: Your setup is a single page for their OS and path, remembered. Sharer: Start explains itself in a WhatsApp preview. Returner: a header banner and What's new. Interview and harness keep anchors so they can still be linked.

3.2 · The first ten seconds: promise + the choice itself

At 1280×800 the headline, a two-sentence explanation and the “Find your first step” card share the first screen, so what / who / next are all visible. On 390 px the headline and plain-language paragraphs come first, and the choice card is one thumb-scroll away. The idea becomes concrete in the next band: the same two words, “Morning briefing.”, asked of a stranger and of an assistant that has read your notes. That before/after makes “a memory of you” tangible without mascots, screenshots or jargon.

3.3 · Choosing the way in: infer one, ask one

OS is inferred (shown as pre-selected, easy to change). Only one question is asked: how you'd like to use AI, phrased by what it feels like, not by tool category. Picking an answer is the navigation, so the comfort-2 Windows visitor reaches their setup in one interaction; same for the comfort-4 Mac user picking “From the terminal”. The difference is in what they get: path A has the most explanation and paste-instead-of-write checks; path C drops the “why” paragraphs and is terse. Download zip and read-online stay as secondary links; the app is labelled “coming later”, not a dead button. Windows is never a footnote: its steps have their own copy (Extract All, locked-down work laptops).

3.4 · Setup as a companion

Progress, OS and path live in localStorage. On return, a header strip says “Setup paused at step 3 of 5” with one button, and the setup page opens with the current step expanded and scrolled into place (≤ 1 interaction). Across devices, a plain link carries OS, path and step (/setup#mac-b-3): no account, nothing stored anywhere else. On a phone, “Send this to my computer” uses the system share sheet. Steps reuse the harness marks ([ ] [/] [x]) and its Done when / Check pattern, so Day 1 already teaches the system.

3.5 · Prompts as first-class objects

One component everywhere: a card with a name, a big Copy button (44 px target) and the prompt in monospace. Placeholders keep their angle brackets, get a dashed underline and highlight (distinguishable without colour), and are real text fields: type into them and the copy includes your words; leave them and the copy keeps <Name>. Two contexts show personalisation: in the library the stuck-on-a-step prompt is raw; inside a setup step it arrives pre-filled with your OS and AI tool, marked as editable.

3.6 · The catalog: a menu

Typeset like a restaurant menu: area headings with a rule, dish name, a one-line description and a small level tag (S, M, L, with the meaning in words and a tooltip). Ticking a line tints it and updates a tray. One filter only, by effort, because “what can I do today?” is the beginner's question; areas are a jump row, not a filter. The tray covers the empty state (“most people end up with 5–10”), the 12-picked state (“12 picked from 5 areas”) and the copy moment, with the full message previewable before copying.

3.7 · Identity: evolve, and drop the violet

Evolve. The warm editorial serif already says “written by a person”; I keep it (system serifs: Iowan, Palatino, Georgia, so zero font requests). Violet goes: it's the default colour of AI products and works against “not a startup”. In its place: warm paper and ink, one moss green for actions, a highlighter yellow reserved for things you fill in. Monospace is used only for real artefacts (file names, prompts, status marks), so “plain files you own” is visible in the type itself. The mark is a note with a seed in it. No illustration and almost no motion. All tokens are CSS custom properties with light and dark sets, ready for a webview app.

3.8 · Progress without homework

No percentages, streaks or badges. The plan is split into “The first month” (P0–P2) and “Whenever you're ready, if ever” (P3–P7). The journey row ends in a dashed line marked optional. Skipping is presented as a valid status. The one sentence, “Continue my harness plan.”, means nobody has to remember where they were.

3.9 · Trust without legalese

Trust is earned where the doubt appears: right before the download, as six plain questions (cost, where notes go, what's in the zip, what open source means, tracking, who made it). “Open source” is translated into “every file is public, anyone can read and check it”. The zip is described by size and contents. The privacy promise repeats in the footer, and the site keeps it: no cookies, no analytics, no third-party requests.

What transfers to a desktop app

Transfers: the token set (colours in both modes, three font stacks, radii, 44 px targets); primitives: Prompt card with fillable placeholders, step card with status mark + Done when/Check, choice pills, menu row with checkbox, tray; the voice rules. Stays web-only: OS/path choosing (the app knows its OS), the trust band and before/after (persuasion is done by then), shareable setup links, hash routing and the What's new banner (an app would update itself).
